# 작업 규칙 문서화 계획

- 상태: 로컬 문서 작성·검증 완료. 커밋·push·PR 생성은 하지 않았다. 사용자와 확정한 규칙만 반영했다.
- 목표: 다음 작업자가 권한 범위, 브랜치 흐름, 작업별 문서와 검증, 커밋·PR 작성 방식을 찾을 수 있게 한다.
- 범위: Django 저장소의 규칙·PR 양식·안내 문서. 애플리케이션 코드, 의존성, 다른 저장소, 외부 설정은 변경하지 않는다.
- 기준: 현재 기반 커밋이 병합된 `main`의 `fd085c43f038e541bdbcac8bf0144540706b2275`에서 생성한 `docs/agent-rules` 브랜치.

## 현재 사실

- Phase 0-A 로컬 개발 기반은 병합되었다. 기존 실행 증거는 [개발 기반 계획](phase0-foundation.md)에서 찾는다.
- `AGENTS.md`는 초기 안내만 있으며 상세 작업 규칙과 PR 양식은 아직 없다.
- 공통·Django 제품 계획 원본은 현재 저장소 바깥에 있다. 저장소 내 명세 snapshot 연결은 후속 작업이다.
- `dev`, 공통 검증 스크립트, CI, AI 리뷰, 최신 SHA에 결속된 사람 승인 게이트는 아직 없다.

## 변경 파일과 순서

1. 이 계획에 범위와 완료 조건을 기록한다.
2. `AGENTS.md`에 짧은 공통 규칙과 상세 문서 진입점을 둔다.
3. `docs/runbooks/task-workflow.md`에 작업별 읽기·수정·검증·보고와 Git 규칙을 기록한다.
4. `.github/pull_request_template.md`에 사람이 채워서 사용하는 상세 PR 양식을 둔다.
5. `README.md`와 기존 개발 기반 계획에 현재 상태와 연결 경로를 반영한다.
6. 문서 검증 후 결과를 보고한다. 커밋·push는 하지 않고 PR도 생성하지 않는다.

## 완료 조건과 검증

- 허용된 여섯 작업 브랜치 유형과 `main`·`dev`의 명명 예외가 일관된다.
- `dev` 생성 시점은 기반 작업 완료 이후이며, 미병합 선행 브랜치를 기반으로 작업하지 않는다.
- 커밋·push의 별도 승인, 사용자의 수동 PR 생성·검수·병합이 명확하다.
- 커밋 제목과 본문, 상세 PR 양식이 합의한 한국어 작성 규칙을 따른다.
- 존재하는 검증과 미구현 하네스·외부 보호 설정을 구분한다.
- Git Bash에서 `git diff --check`, 변경 파일의 UTF-8·링크·앵커·코드 펜스·충돌 표식 검사와 규칙 대조를 수행한다. 신규 파일도 별도로 검사한다.
- 문서만 변경하므로 애플리케이션 테스트·Docker 실행은 이번 검증 범위에 포함하지 않는다.

## 실패 시 대응

문서 검사 실패는 해당 문서에서 수정하고 다시 검사한다. 확정되지 않은 정책이나 명세 경로 선택이 필요하면 질문한다. 기존 코드·기록·사용자 변경을 삭제하거나 Git 이력을 되돌리지 않는다. 이 작업에는 실행 환경 변경이 없어 서비스 복구 작업은 필요하지 않다.
